# Pytest-проверки сайта #PROSHKA

Набор автоматических проверок публичного сайта методом «чёрного ящика». Тесты отправляют только GET-запросы: формы не отправляются, персональные данные не используются.

## Запуск в VS Code (Windows)

Открой папку `PROSHKA_Pytest` в VS Code и выбери **Terminal → New Terminal**. Выполняй команды по одной:

```powershell
py -m pip install -r requirements.txt
py -m pytest --collect-only -q
py -m pytest -v
```

Если `py` не работает, можно попробовать `python` вместо `py`.

## Что проверяется

- доступность главной страницы и URL с `utm_source=chatgpt.com`;
- доступность страницы партнёрства, пяти разделов и страницы проекта;
- присутствие полей формы по `name`/`id` или типу input (HTML декодируется с учётом `charset`);
- упоминание политики обработки персональных данных или ссылки на политику;
- доступность основных CSS- и JS-файлов;
- использование HTTPS после перенаправлений;
- наличие базовых защитных HTTP-заголовков;
- доступность `.env` и `.git/HEAD` по типичным публичным путям без вывода содержимого ответа.

## Как понимать результат

- `PASSED` — проверяемое условие выполнено.
- `FAILED` — условие не выполнено; результат нужно проанализировать. Например, отсутствие заголовка безопасности является замечанием по конфигурации, но само по себе не доказывает возможность взлома.
- `SKIPPED` — автоматическая проверка не смогла однозначно классифицировать ответ и требует ручного просмотра.

Проверки `.env` и `.git/HEAD` считают любой ответ HTTP, отличный от `200`, неуспешным получением файла. Код `405 Method Not Allowed` не трактуется как доказательство публикации файла. Если получен `200`, тест ищет только узнаваемые признаки формата и не выводит содержимое ответа.

Тесты не проверяют кабинет Web3Forms, доставку заявок на почту, серверную обработку, права доступа к заявкам, фактическую юридическую достаточность согласия или производительность сайта. Они не заменяют ручное тестирование и аудит сервера.
